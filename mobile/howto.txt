========================================================================
                      LOCALIFY — GUIA DE FUNCIONAMENTO (HOWTO)
========================================================================

Este documento explica de maneira detalhada e estruturada como o código do 
Localify funciona, mapeando a arquitetura do aplicativo, a ponte nativa, 
o motor de busca e as otimizações essenciais aplicadas para garantir um 
download de áudio e letras rápido, offline e resiliente.

---

1. VISÃO GERAL DO APLICATIVO
========================================================================
O Localify é um reprodutor de áudio offline que permite sincronizar e 
baixar playlists completas do Spotify diretamente para o celular. 

Para que isso funcione sem a necessidade de servidores externos pesados ou
infraestrutura complexa de transcodificação, o aplicativo utiliza uma 
arquitetura híbrida:
- INTERFACE & FLUXO (Dart/Flutter): Gerencia o estado, telas e banco SQLite.
- PONTE NATIVA (Kotlin/Android): Spawna threads secundárias e carrega a Chaquopy.
- MOTOR DE DOWNLOAD (Python/yt-dlp): Realiza buscas e downloads de fluxos de 
  áudio nativos em formato AAC (.m4a) diretamente do YouTube.

---

2. MAPEAMENTO DE COMPONENTES E ARQUITETURA
========================================================================

Abaixo está o detalhamento técnico do papel desempenhado por cada arquivo
chave no ecossistema do Localify:

A) INICIALIZAÇÃO E LAYOUT
------------------------------------------------------------------------
* Arquivo: `lib/main.dart`
  - Define a orientação do app para retrato fixo (portrait).
  - Torna a barra de status transparente para criar uma interface visual imersiva.
  - Inicializa o banco de dados local SQLite (`AppDatabase.instance.init()`).
  - Inicializa o `AudioService` global para que o áudio continue tocando em 
    segundo plano (background playback) com integração nativa na barra de 
    notificações do celular.

B) PERSISTÊNCIA LOCAL (BANCO DE DADOS)
------------------------------------------------------------------------
* Arquivo: `lib/data/database/database.dart`
  - Gerencia o SQLite do celular usando o pacote `sqflite`.
  - Tabela `playlists`: Guarda metadados das playlists adicionadas e o 
    `snapshot_id` do Spotify para controle de cache inteligente.
  - Tabela `tracks`: Entidade que guarda metadados individuais das músicas, 
    código ISRC (para buscas exatas), flag de cache, arquivo físico associado 
    e o status do download (`pending`, `downloading`, `success`, `failed`).
  - Cura preventiva de Status: Ao iniciar o app, ele executa um reset automático, 
    mudando faixas travadas em `downloading` de volta para `pending` (caso 
    o app tenha sido fechado abruptamente).

C) SINCRONISMO COM SPOTIFY
------------------------------------------------------------------------
* Arquivo: `lib/data/services/spotify_service.dart`
  - Utiliza o fluxo de autenticação Client Credentials (ID e Secret configurados 
    pelo usuário nas configurações do app) para gerar tokens sob demanda.
  - Compara o `snapshot_id` da playlist remota com o local: se forem iguais, 
    pula a atualização de metadados para poupar processamento e conexões de rede.
  - Efetua requisições paginadas de 100 em 100 faixas para compilar a lista 
    completa das músicas do Spotify com precisão.

D) COORDENADOR DE FLUXO (SYNC SERVICE)
------------------------------------------------------------------------
* Arquivo: `lib/data/services/sync_service.dart`
  - É a "central de controle" da sincronização.
  - Método `syncMetadata`: Requisita novos dados do Spotify, atualiza o SQLite 
    e faz a cura retroativa dos arquivos físicos locais (varre a pasta de 
    músicas e se o arquivo `.m4a` existe fisicamente, marca como `available` 
    no banco).
  - Método `syncAudio` (Fila Resiliente): Executa o loop de downloads. Caso 
    uma música falhe, ela recebe o status `failed`, a tela se atualiza com a 
    falha daquela música e o loop continua imediatamente para a próxima música.
  - Mecanismo Anti-Ban: Aplica uma pausa de 2 segundos após downloads concluídos 
    com sucesso para proteger o IP do usuário contra bloqueios agressivos do YouTube.
  - Dispara de forma assíncrona o download de letras.

E) DOWNLOAD DE LETRAS OFFLINE (LYRICS SERVICE)
------------------------------------------------------------------------
* Arquivo: `lib/data/services/lyrics_service.dart`
  - Consome as APIs públicas do `LrcLib.net`.
  - Tenta primeiro buscar a letra por correspondência exata do ISRC ou combinando 
    Artista, Título e a duração exata da música (para evitar pegar letras de 
    covers, edições ao vivo ou estendidas).
  - Faz o parse de arquivos no formato sincronizado LRC (`[minuto:segundo.centésimo] texto`).
  - Salva um arquivo físico `.lrc` na mesma pasta do áudio da música. Assim, as 
    letras acompanham o tocador de forma 100% offline e com rolagem automática no tempo exato.

F) PONTE DE PROGRAMAÇÃO NATIVA (DART ↔ KOTLIN)
------------------------------------------------------------------------
* Arquivo: `lib/data/services/native_downloader.dart`
  - Lado Flutter da ponte. Prepara as pastas locais de destino e verifica/salva 
    o arquivo de cookies de autenticação (`yt_cookies.txt`).
  - Invoca o `MethodChannel('com.localify/downloader')` com as informações da faixa.
  - Uma vez que o download nativo conclui no caminho temporário, ele sanitiza 
    o nome final do arquivo, copia-o para a pasta permanente e apaga o temporário.

* Arquivo: `android/app/src/main/kotlin/com/example/localify/MainActivity.kt`
  - Lado Android/Kotlin da ponte. Escuta as chamadas do MethodChannel.
  - Inicializa o ambiente Python da Chaquopy.
  - SEGURANÇA VISUAL: Spawna uma nova Thread física no Android para executar 
    o script Python de download. Isso é crítico, pois o processamento de rede 
    do Python não bloqueia a UI Thread do Flutter, permitindo que a interface 
    do aplicativo permaneça lisa, responsiva e com animações fluidas na tela.

G) MOTOR DE EXTRAÇÃO PYTHON
------------------------------------------------------------------------
* Arquivo: `android/app/src/main/python/downloader.py`
  - Script executado no celular através do interpretador embutido Chaquopy.
  - Recebe os dados de música do Java/Kotlin, converte o HashMap Java para um 
    dicionário nativo do Python (evitando problemas de sobrecarga de métodos 
    com assinaturas de tipos diferentes).
  - Executa o motor do `yt-dlp` configurado para extrair o fluxo de áudio nativo 
    no formato `140` (AAC / .m4a em 128kbps).
  - BENEFÍCIO DO FORMATO 140: Como o YouTube fornece nativamente o arquivo M4A 
    com o codec AAC pronto, o app pode salvar o arquivo diretamente no celular 
    sem precisar do utilitário FFmpeg para transcodificar, poupando espaço de 
    armazenamento e processamento no celular.
  - Seleção por Duração: Caso haja buscas múltiplas, a função `_pick_best_by_duration` 
    analisa os metadados dos vídeos e seleciona aquele cuja duração seja a 
    mais próxima da informada pelo Spotify, eliminando podcasts, reacts e lives.

3. O PASSO A PASSO DE UM DOWNLOAD SUCEDIDO
========================================================================

Quando você clica em baixar uma playlist ou música:

1. O Flutter (`SyncService`) seleciona as faixas com status `pending` (não disponíveis).
2. Ele atualiza o banco local daquela faixa para `downloading` (atualizando a UI do app).
3. Chama o `NativeDownloader` (Dart) que envia o título, artista e duração via 
   MethodChannel para o Android.
4. O `MainActivity` (Kotlin) recebe, joga o processamento em segundo plano e 
   chama `download_track` no arquivo Python `downloader.py`.
5. O Python recebe os metadados, traduz o HashMap Java em um dicionário Python e
   tenta buscar no YouTube usando queries do tipo `ytsearch1:Artista - Titulo official audio`.
6. O `yt-dlp` realiza a pesquisa. Se for uma busca múltipla (retry), ele analisa
   as durações dos primeiros 5 resultados e escolhe o melhor match de tempo.
7. O `yt-dlp` inicia o download do arquivo de áudio diretamente no formato 140 
   (AAC nativo .m4a) salvando-o no diretório temporário indicado.
8. Uma vez finalizado, o script Python retorna o caminho do arquivo de áudio temporário 
   para o Kotlin, que devolve ao Flutter via MethodChannel.
9. O Flutter renomeia o arquivo para o formato amigável `"Artista - Titulo.m4a"`, 
   move-o para o diretório físico permanente da playlist e deleta o arquivo temporário.
10. O banco de dados SQLite local é atualizado: o status vira `success` e a faixa 
    é marcada como `available = 1` (disponível para reprodução imediata).
11. O serviço de letras busca e salva as letras no formato `.lrc` de forma silenciosa.

4. DETALHE DAS CORREÇÕES E OTIMIZAÇÕES RECENTES
========================================================================

Para que o aplicativo passasse a funcionar de forma estável, rápida e sem falhas,
aplicamos as seguintes otimizações críticas de estabilidade:

1. Fim do Abortamento por Consecutivas Falhas:
   - Removido o limite rígido no Dart que abortava toda a fila se 3 músicas 
     falhassem seguidamente. Músicas ruins ou bloqueadas não barram mais o download 
     do resto da playlist.

2. Conversão Automática Java HashMap -> Python Dict:
   - A ponte da Chaquopy criava um wrapper Java HashMap para o dicionário Python,
     o que gerava erros graves como `TypeError: java.util.HashMap.get takes 1 argument (2 given)` 
     ao usar o clássico `dict.get(key, default)`. Agora, a conversão limpa garante
     segurança total no Python.

3. Abandono do Protocolo Incompatível `ytmsearch`:
   - A busca específica do YouTube Music (`ytmsearch`) causava erros graves de 
     esquema incompatível com o urllib no ambiente do celular. Substituímos todas 
     as pesquisas para usar o confiável e compatível `ytsearch`.

4. Downloads Muito Mais Rápidos (Fast Fail):
   - Reduzimos o timeout de conexão do downloader Python de infinito para 10 segundos.
   - Limitamos as tentativas de downloads internos no yt-dlp para no máximo 2 
     (evitando que o app fique preso tentando baixar faixas indisponíveis).
   - Zeramos a taxa de espera artificial entre requisições internas do Python.

5. Tratamento de Rate Limit Dinâmico e Curto:
   - Antigamente, quando o YouTube aplicava um Rate Limit (HTTP 429), o Python 
     congelava o download por 90 a 300 segundos. 
   - Reduzimos este intervalo para um backoff dinâmico curto: começa em apenas 
     5 segundos e vai dobrando até no máximo 15 segundos. Isso destravou o fluxo 
     de downloads mantendo a segurança.
